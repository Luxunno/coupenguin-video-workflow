# 凑企鹅视频创作工作流

帮助用户把一句构思、一段音频或一条参考视频做成凑企鹅作品。Agent 负责查找素材、配置工具、搭建场景、编排动作和镜头，用户负责表达想法、需要时录音，以及在 GMod 中查看搭建效果。

既可以把现有视频改编成凑企鹅版本，也可以从零创作对白小剧场、唱歌、跳舞、梗视频或其他题材。角色、道具、地图、动作、声音和表现方式都可按创意更换，不以旧会话的抱玩偶唱歌案例为固定模板。

## 工作方式

### 1. 先和用户确认大致脚本

开始环境配置、素材下载和场景制作之前，先与用户交互，确认这部视频大致要讲什么、怎么演。

围绕人物、场景、主要事件或笑点、大致时长和声音来源沟通。用户已有想法时，先整理成简短脚本；只有一句构思时，给出一个可修改的草案，或少量方向供选择。声音来源可以是已有音源、语音包，也可以由用户录音。

把开场、主要表演和结尾写清楚，连同关键台词或音源一起交给用户确认。收到确认后再开始制作；用户已经明确确认过的内容不重复询问。这里确认的是创作方向，不要求用户事先决定所有动作、镜头参数和技术细节。

- 参考改编：判断用户想借用哪些元素，再设计凑企鹅版本，可以改剧情、动作、运镜、节奏和结尾。
- 从零创作：把构思展开为简短剧情和分镜；素材与技术选择服务于创意。
- 续作修改：接着已有工程改，不重新要求用户描述已经确定的内容。

用简短分镜表记录“这一段发生什么、角色做什么、镜头怎么看、声音是什么”。简单作品用表格即可，需要脚本控制时再生成时间线，不要求所有项目填写固定配置文件。

### 2. 准备环境和素材

确认大致脚本后，Agent 自己拆出角色、地图、道具、动作、语音和音效需求，按 [素材检索与扩展](references/discovery.md) 查找、下载和整理。先找随包语音、本地素材和已安装的 ActMod，再补充语音网站、工坊与创作者原始发布页。新机器按 [环境配置](references/setup.md) 准备工具。

用户不需要知道文件名、动作名或工坊 ID。能从描述确定的资源由 Agent 直接选用；只有私有素材、登录或明显影响创作方向的歧义才请用户介入，其他工作继续进行。

### 3. Agent 匹配动作、适配素材并搭建分镜

动作优先从 ActMod 和现有动画中按用户描述匹配。例如“得意地扭两下”先转成情绪、动作特征和持续时间，再寻找或组合可用动作；不要求用户报出动作名称。用户有偏好时，也可以在 ActMod 中自己选。

找到资源后，Agent 继续负责骨架匹配、动作速度与衔接、道具接触、语音裁切、停顿和音量，完成可观看的表演。缺少现成动作时，尝试动作组合、关键帧或其他资源；需要用户手动微调时，先搭好场景并定位到具体姿势。没有合适台词可安排录音再换声，缺少道具可改造或建模。替代方案明显改变原意时，再说明差异并让用户决定。

按 [动作与场景](references/animation.md) 组织表演。没有合适模型或需要改造型时，再读 [建模与导入](references/modeling.md)。

Agent 使用 GMod Lua、PAC3 配置、动作插件或 Blender 脚本完成制作。具体采用哪种工具取决于素材和效果，不规定每个项目都走同一条路线。自动化组织方法见 [Agent 制作与拍摄](references/automation.md)。

### 4. 集中检查一次样片，再请用户在 GMod 中看效果

场景、动作和分镜搭好后，在邀请用户看 GMod 效果之前，集中做一次低成本样片检查，看看是否有明显穿模、错误动作、镜头遮挡或漏掉的剧情段落。发现问题由 Agent 修正，不在每个小步骤反复导出样片或要求用户验收。

明确匹配的资源直接放进样片和 GMod 预览，不逐项请求批准。只有不同候选会明显改变笑点、剧情或风格时，才展示少量可试听或可观看的候选，并用一句话解释差别，避免让用户浏览一堆链接。

随后提供一个容易进入的 GMod 预览：角色已就位，动作与镜头可以播放、暂停和重播，并说明预览入口。请用户集中看角色造型、动作、构图、节奏和场景，Agent 根据反馈修改。用户不必逐骨骼调整；也不需要哈希或全帧校验。

### 5. 做声音

优先使用随本包放置的“高松灯爱音语音包”，位置为本 Skill 目录下的 assets/voice-packs/高松灯爱音语音包/。其中包含用户提供的常用咕咕嘎嘎等语音；Agent 先搜索实际文件名、试听候选并匹配脚本，合适的直接使用，不必让用户再次寻找音源。使用方法见 [内置语音包](references/voice-pack.md)。

按 [音源、录音与 RVC](references/audio-edit.md) 选择：

- 导入已有音频或从视频提取音频，再换声。
- 用户用麦克风录音，再换声。

根据创作需要安排声音制作顺序：台词驱动的小剧场可以先录音再编排动作，画面优先的作品也可以后配音。音乐、对白和音效在剪辑中对齐。

### 6. 拍摄和剪辑

用户看过 GMod 效果并给出意见后，完成调整，选择合适的录制或渲染方式，加入换声、音乐、音效和字幕，导出成片。按 [预览与交付](references/validation.md) 进行简单的播放和试听检查即可。

## 素材扩展

用过的资源逐渐积累到本地素材库，保存名称、别名、来源、用途和位置即可。语音可标注“惊讶、尖叫、咕咕嘎嘎”，动作可标注“得意、扭腰、庆祝”；下次先复用，缺少时再联网找。索引使用普通 JSON 或表格，不需要数据库或哈希系统。

ActMod 中成功应用的动作也记录适用模型、内部名称和必要调整。用户自己挑选或手动微调的结果同样保存，避免下次重复劳动。资源库服务于创作，不把作品限定为已有几种素材。

“咕咕嘎嘎”等词先结合上下文判断是要音源、台词、动作还是整体风格，再查找对应内容。取得语音后按名称整理，方便脚本选用。素材检索和技术资料的来源见 [参考资料](references/evidence.md)。

## 交付

提供成片和可编辑工程，简要说明下次从哪里继续改角色、动作、声音与分镜。使用了哪些第三方素材，保留相应来源。

详细文档提供制作方法和可选实现方式，Agent 应根据具体作品组织工作。
