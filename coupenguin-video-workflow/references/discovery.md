# Agent 自动获取资源与本地素材库

## 从已确认脚本开始

大致脚本由用户确认后，Agent 将每个段落拆成角色、场景、道具、动作、语音与音效需求，自己查找、下载和整理。需求清单用简短表格即可，已有资源直接填入，不让用户逐项补文件路径。

用户说“企鹅一边咕咕嘎嘎，一边得意地扭两下”时：
- 角色：当前企鹅模型。
- 语音：随包语音中的咕咕嘎嘎及近似别名。
- 表演：得意的情绪、腰或身体左右摆动、两次动作。
- 衔接：语音何时进入、扭动与语音的关系、如何收尾。

Agent 据此选择音频和动作，剪切或组合成一个表演。除非含义确实会影响剧情，不追问“音频在哪里”“动作叫什么”或“工坊 ID 是多少”。

## 资源查找顺序

| 资源 | 先找 | 不够时 |
|---|---|---|
| 常用语音 | [随包高松灯爱音语音包](voice-pack.md)、已有项目素材库 | 常用语音网站、原音作者、B 站等公开视频音源 |
| 动作 | 已安装 ActMod、角色 sequence、已用过的动作 | 动作插件、工坊、创作者发布页，或自行组合/做关键帧 |
| 角色、道具 | 当前工程和已下载模型 | 工坊、作者发布页，必要时改造或建模 |
| 地图、场景 | 已安装地图和已保存机位 | 工坊地图、依赖内容或自建布景 |
| 音效、音乐 | 已有素材和用户指定参考 | 公开素材来源、作者资源页或其他匹配来源 |

查找沿着当前作品需求进行，不下载整个互联网站点或无关合集。找到足够合适的资源就进入制作，避免把搜索变成额外研究项目。

### 查到之后由 Agent 继续做

1. 查看原条目与依赖，获取所需素材。
2. 放进本地素材目录并保留来源，解压或整理分类。
3. 在实际制作环境中加载，处理必要的格式转换和依赖。
4. 按本片需要适配，放进场景和时间线。
5. 将成功使用的结果登记到素材索引。

用户指定的私有文件、必须本人登录的内容或真实权限限制才需要用户介入；说明缺少的具体内容，其他搭建继续。资源已公开可取得时，不把下载任务退给用户。

## 从自然语言得到检索词

同时保留用户原词、别名和动作/情绪描述：
- 咕咕嘎嘎 / 姑姑嘎嘎 / gugu gaga / goo goo ga ga。
- 得意地扭两下 → 得意 / 扭腰 / 摆动 / 庆祝，加 sway / wiggle / dance 等描述。
- 企鹅高松灯 / Takamatsu Tomori Penguin。
- fumo / fufu / ふもふも，加角色名、模型或 model。

文字匹配用于找候选，语音靠实际声音、动作靠实际播放确认。拟声词的转写可能不准；同一个梗也可能有不同速度、语气和变体。资源标签可以交叉组合，不把一个用户词固定绑定到一个资源 ID。

## 声音资源

优先递归查看随包语音文件和已有索引，按角色、台词、情绪和音长选用。文件名不清楚时再试听并补标签，不要求用户重新整理整包。

常用补充入口：[语音网站](https://apps.125ks.cn/qwyy/gxd2/)。
需要补充时读取页面实际音频条目和公开地址，按名称下载；若分分类或分页则遍历当前语音页。按地址去重即可，保存名称、来源和本地文件位置。网页下载和用户提供的随包素材分开记录。

从视频获取音源时记录片段位置，提取后裁切。找到合适目标声线的音频直接使用；需要换声才进入 RVC。始终保留原音频，把本片剪辑副本放在制作工程中。

## 动作与工坊资源

动作优先通过 ActMod 的分类、动作展示名称、插件注册表和可用 sequence 来匹配。能访问动作列表时由 Agent 搜索并选用；用户想自己挑选时提供 ActMod 入口，选择结果仍由 Agent 负责后续应用。

工坊检查资源类型与依赖：角色的表情/骨架、地图的附加内容、动作的载体模型、道具是否可变形。动作显示名、内部 sequence、载体路径和工坊 ID 分别记录，不能互相当作同一个值。

历史搜索起点可用 [企鹅高松灯](https://steamcommunity.com/sharedfiles/filedetails/?id=3661868512) 和 [ActMod](https://steamcommunity.com/sharedfiles/filedetails/?id=2538387266)，也可按实际需求选择其他来源。

## 下载后完成适配

| 资源 | Agent 负责的处理 |
|---|---|
| 动作 | 骨架映射、速度、起止、循环、过渡和道具接触 |
| 语音 | 裁切、停顿、音量、入点；仅必要时换声 |
| 音效 | 与动作发生点对齐、音量和尾声 |
| 模型、道具 | 比例、朝向、材料、握点和必要骨架调整 |
| 地图 | 角色站位、布景、灯光和机位 |

技术处理完成后合进作品预览，不让用户分别检查每个导入文件。

## 本地素材库怎样积累

优先沿用已有素材目录；没有时建立一个简单目录和 index.json 或表格。当前项目可以直接使用，后续作品也可复用同一素材库，不要求建立服务或数据库。

每项记录：
- 名称、类别、别名与用途标签。
- 来源页面或“用户提供”。
- 相对于素材库的文件位置；动作则记录插件、载体与内部名称。
- 成功用在什么角色或场景，以及必要的使用备注。

只把实际找到的文件和成功使用的映射写入索引。语音的实际台词、时长、动作内部名称在读取或使用后填入，不猜造。未使用的候选可以留在搜索笔记，不和可直接复用的素材混在一起。

采用文件名或原地址去重即可；同名不同版本保留区别。索引中的标签帮助查找，并不取代实际试听或播放。下次同类请求先查索引，再检查对应资源仍可用，缺少时继续寻找。

用户挑选的动作、手动微调后的姿态、常用机位与 Agent 的适配结果也可以保存为可复用配置。

## 减少打断

资源明确匹配时直接用，在预览中一起展示。只有不同候选会明显改变笑点、剧情或风格时，才集中呈现少量候选，附试听/动作演示和差异说明，让用户做创作选择，不让用户做资源检索工作。

小段候选试听或 ActMod 试播不需要额外导出视频样片。样片仍然只在邀请用户进 GMod 看效果之前集中检查一次。

## 没有现成素材时继续推进

- 动作：尝试其他现有动作、拼接或关键帧；用户愿意时也可在已搭好的场景中手动调整，由 Agent 保存结果。
- 台词：找近似语气的可用内容；必须保留原台词时安排用户录音再换声，不偷偷改对白。
- 道具：改造已有模型或建模。
- 场景：选符合脚本的地图或自行布景。

不改变原意的小型适配由 Agent 完成；替代方案会明显改变用户想要的内容时，用“原方案缺什么、替代后有什么差别”简短说明，再让用户决定。等待时继续能独立完成的部分。
