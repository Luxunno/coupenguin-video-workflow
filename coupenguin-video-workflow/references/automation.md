# Agent 制作与拍摄

## 自动化的目的

让用户提供创意和审阅意见，Agent 负责重复操作、素材整理和分镜调整。实现方式随项目选择：GMod Lua、PAC3 配置、动作插件、Blender 脚本或编辑器工程都可以。

简单作品不必先搭一个通用执行框架，也不需要 job_id、哈希、锁文件、心跳或强制状态报告。

## 制作入口：先确认脚本

先把用户想法整理成简短脚本，确认人物、情节或表演、声音来源和大致结尾。给用户一个可直接修改的草案，等方向确认后再搭建；详细镜头和技术实现由 Agent 继续完成。

## 资源获取与适配由 Agent 承接

脚本确认后，按段落列出所需资源，先查随包语音、本地索引和 ActMod，缺少时再搜索公开来源并下载整理。用户无需提供技术名称或逐项确认明确匹配的资源。

下载、载入、适配、加入时间线是一段连续工作。具体方法见 [素材检索与扩展](discovery.md)。用户选择的动作或微调的姿态同样由 Agent 接回工程并保存，避免出现“资源已经找到，但还要用户自己配置”的断点。

## 工程怎么组织

至少能找到角色/场景文件、动作与镜头设置、音频和成片即可。复杂项目可以分成 assets、scene、audio、output 等目录。已有工程沿用原结构，不为符合模板搬迁全部文件。

分镜表是创作说明。需要程序控制时，将它转成脚本实际读取的时间线；可以用秒或帧，但音画要采用一致的时间基准。

可选时间线示意：
```json
{
  "fps": 30,
  "shots": [
    {"start":0,"end":3,"camera":"door","actor_action":"enter"},
    {"start":3,"end":6,"camera":"closeup","actor_action":"look_surprised"}
  ],
  "audio": [
    {"start":1,"file":"voice/line_01.wav"},
    {"start":3.5,"file":"sfx/reaction.wav"}
  ]
}
```
这里是字段示意，不是 GMod 内置格式。Agent 按实际工程编写读取代码，动作和机位来自当前项目。

## 场景和动作脚本

初始化角色、道具和灯光后，把动作、镜头、表情分别控制。修改声音或机位时，不必重建所有资源。

需要自定义 addon 时，可分为：
- 场景加载：角色、道具、地图与材质。
- 表演控制：动作、骨骼、表情和道具互动。
- 镜头控制：机位、切换、移动与视角。
- 预览控制：播放、暂停、重播、跳到某镜头。
- 拍摄控制：选择录屏或画面输出。

这里只是组织建议，短项目合在一个脚本中也可以。命令或按钮由 Agent 实际实现后再告诉用户，不把设想中的名称说成已经存在的功能。

## 预览是主要的用户介入点

场景、动作和分镜搭好后，先集中导出并检查一次低成本样片，修正明显的场景、动作和镜头问题，然后请用户进入 GMod 看：
- 人物和道具是否符合想法。
- 动作和表情是否到位。
- 镜头、场景与节奏是否喜欢。
- 哪些位置需要调整。

资源选择合在预览中展示，用户用“更得意一些”“换个语气”等自然语言给反馈即可。候选明显影响剧情或风格时再提前给少量可试听/可观看的选择，不逐项发链接。

记录用户反馈并在现有工程中修改。样片默认只在这次用户预览前检查一次，不在每个阶段安排样片验收，也不做全帧扫描。样片和 GMod 预览可配临时声音，也可使用已经完成的换声，取决于制作顺序。

## 拍摄方式按作品选择

### 实时录制

适合动作、特效和游戏表现都能实时播放的项目。设置分辨率和录制帧率，清理画面，播放安排好的镜头，用合适录屏工具录制。分镜可以分段拍摄，再剪辑拼接。

### 脚本输出画面

需要精确镜头、较高画质，或实时性能不足时，可逐帧渲染再合成。让场景按指定时间更新，然后在渲染回调中输出图像。

[render.Capture](https://wiki.facepunch.com/gmod/render.Capture) 需要在合适渲染时机调用；拍到黑屏或空内容时检查游戏菜单和渲染上下文。输出不需要透明背景时关闭 alpha。用完的渲染状态和临时对象应正常恢复。

逐帧方式只是可选拍摄手段，不增加额外的样片检查节点、哈希系统或全帧验收流程。

### Blender 拍摄

自建复杂角色、特殊镜头或动画适合 Blender 时，可以使用同一分镜在 Blender 完成相应镜头，再与 GMod 镜头剪辑组合。用户要求全 GMod 时遵从该要求。

## 修改与继续制作

保留工程和已有录制素材。只改声音就重新混音；只改镜头就重拍该镜头；角色动作有变化则更新对应表演。判断是否复用，以当前修改涉及什么为准，无需计算文件哈希。

用户确认 GMod 预览后开始正式拍摄；后续有小修改继续在原工程中完成。
